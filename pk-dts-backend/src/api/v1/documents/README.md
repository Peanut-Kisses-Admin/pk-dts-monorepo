# Documents API

Softcopy documents accept `softcopy_category_id`. Revision uploads are stored under
`uploads/revisions/<category-folder>/`, while API responses expose the nested browser-safe
`file_url` and retain the original `file_name` for display and download.

Base path: `/api/v1/documents`

This is the main document tracking module.

## Endpoints

- `GET /` list documents
- `GET /:id` get one document
- `GET /:id/revisions` list revisions for a document
- `POST /` create document
- `PATCH /:id` update document
- `DELETE /:id` delete document
- `POST /batch-hardcopy` import a hardcopy workbook
- `POST /:id/dispose` dispose a document
- `POST /:id/restore` restore a disposed document
- `POST /:id/revisions` create a revision

## List Response

The list endpoint returns paginated document summaries with:

- `document_id`
- `document_number`
- `document_title`
- `document_type`
- `status`
- `created_at`
- `hardcopy`
- `softcopy`
- `creator`

## Create / Update Body

```json
{
  "asset_id": "1",
  "document_number": "DOC-2026-001",
  "document_title": "Quality Manual",
  "document_type": "HARDCOPY",
  "status": "PendingApproval",
  "area_id": "1",
  "specific_id": "2",
  "location_id": "3",
  "sequence_id": "4",
  "created_by": "1",
  "requested_by_user_id": "1",
  "requested_by_name": "QA Supervisor"
}
```

Validation notes:

- `document_number`, `document_title`, `document_type`, and `created_by` are required
- `document_type` must be `SOFTCOPY` or `HARDCOPY`
- Workflow statuses are `Draft`, `PendingApproval`, `ForRevision`, `Approved`, `Rejected`, and `Disposed`; clients change status only through workflow action endpoints.
- manual document creation defaults to `Draft` when `status` is omitted
- batch hardcopy import always creates `Approved` documents automatically
- `requested_by_user_id` is optional and defaults to the creator when omitted
- `requested_by_name` is optional when a manual requestor label should be stored
- `disposal_remarks` is required whenever `status` is `Disposed`
- IDs must be sent as strings
- Hardcopy documents require `area_id` and `location_id`
- `asset_id` links the document to a standalone asset number record

## Batch Hardcopy Import Body

`POST /batch-hardcopy` uses `multipart/form-data`.

Fields:

- `created_by` required
- `file` required

Notes:

- Accepted file types are `.xlsx` and `.xls`
- The default upload limit is `10 MB`
- The workbook must include `SEQUENCE`, `DOCUMENT NAME`, `LOCATION`, `ASSET NUMBER`, `AREA`, and `SPECIFIC`
- Missing `AREA`, `LOCATION`, `SPECIFIC`, `SEQUENCE`, and `ASSET NUMBER` catalog entries are created automatically before each hardcopy document is saved
- Repeated asset numbers are allowed across multiple hardcopy rows during batch import
- Blank document names are imported with an auto-generated placeholder title so the row can still be saved
- The API parses the workbook on the server and returns per-row created, skipped, and error results

## Detail Response

`GET /:id` returns the document with:

- `hardcopy.asset`
- `hardcopy.area`
- `hardcopy.specific`
- `hardcopy.location`
- `hardcopy.sequence`
- `softcopy.current_revision.uploader`
- `softcopy.revisions[].uploader`
- `creator`

`GET /:id/revisions` returns the revision list for the document's softcopy record.

## Revision Body

`POST /:id/revisions` uses `multipart/form-data`.

Fields:

- `uploaded_by` required
- `file` required
- `reason_of_revision` optional
- `effective_date` optional
- `page_number` optional
- `set_as_current` optional, send `"true"` to make the new revision current

Notes:

- Revisions can only be created for softcopy documents
- `revision_number` is generated by the API and ignored if sent by the client
- The first revision is `000`
- File uploads are limited to 25 MB
- Uploaded files are stored on the local filesystem
