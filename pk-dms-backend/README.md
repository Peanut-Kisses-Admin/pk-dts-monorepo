# Document Tracking System API

NestJS backend using Prisma, PostgreSQL or MySQL, and Cloudinary uploads.

## Setup

```bash
npm install
```

On Windows PowerShell, use `npm.cmd` if `npm` is blocked by execution policy:

```powershell
npm.cmd install
```

The backend now supports environment-based database switching:

- `.env.development` for local development on MySQL
- `.env.test` for testing on MySQL
- `.env.production` for production on PostgreSQL
- `.env` as a fallback only

Default local setup:

```env
DATABASE_PROVIDER="mysql"
DATABASE_URL="mysql://username:password@localhost:3306/document_tracking_dev"
CLOUDINARY_CLOUD_NAME="your_cloud_name"
CLOUDINARY_API_KEY="your_api_key"
CLOUDINARY_API_SECRET="your_api_secret"
CLOUDINARY_FOLDER="document-tracking"
PORT=3000
```

Production setup:

```env
DATABASE_PROVIDER="postgresql"
DATABASE_URL="postgresql://username:password@host:5432/document_tracking_prod?sslmode=require"
```

Generate Prisma Client:

```bash
npm run prisma:generate
```

PowerShell:

```powershell
npm.cmd run prisma:generate
```

Environment-specific Prisma commands:

```bash
npm run prisma:generate:dev
npm run prisma:generate:test
npm run prisma:generate:prod
npm run prisma:push:dev
npm run prisma:push:test
npm run prisma:migrate:dev
npm run prisma:migrate:prod
```

Create database tables:

```bash
npm run prisma:migrate -- --name init
```

PowerShell:

```powershell
npm.cmd run prisma:migrate -- --name init
```

For quick switching, the app and Prisma both read the same environment name and
choose the matching env file and Prisma schema automatically.

Existing migration SQL is database-specific. The current default PostgreSQL
migrations live in `prisma/migrations`; MySQL migrations should be generated
with `DATABASE_PROVIDER="mysql"` and will live under `prisma/mysql/migrations`.
For development databases where you do not need migration history, use:

```bash
npm run prisma:push
```

Start the API:

```bash
npm run start:dev
```

PowerShell:

```powershell
npm.cmd run start:dev
```

Useful app commands:

```bash
npm run start:dev
npm run start:test:app
npm run start:prod
```

## Routes

List routes support pagination:

```text
?page=1&limit=10
```

`limit` defaults to `10` and is capped at `100`.

- `GET /api/v1/health` health check
- `POST /api/v1/auth/login`
- `GET|POST /api/v1/users`
- `GET|PATCH|DELETE /api/v1/users/:id`
- `GET|POST /api/v1/roles`
- `GET|PATCH|DELETE /api/v1/roles/:id`
- `GET|POST /api/v1/permissions`
- `GET|PATCH|DELETE /api/v1/permissions/:id`
- `GET|POST /api/v1/role-permissions`
- `DELETE /api/v1/role-permissions/:id`
- `GET|POST /api/v1/areas`
- `GET|PATCH|DELETE /api/v1/areas/:id`
- `GET|POST /api/v1/specifics`
- `GET|PATCH|DELETE /api/v1/specifics/:id`
- `GET|POST /api/v1/locations`
- `GET|PATCH|DELETE /api/v1/locations/:id`
- `GET|POST /api/v1/sequences`
- `GET|PATCH|DELETE /api/v1/sequences/:id`
- `GET|POST /api/v1/asset-numbers`
- `GET|PATCH|DELETE /api/v1/asset-numbers/:id`
- `GET /api/v1/documents` list documents with related data
- `GET /api/v1/documents/:id` get one document with revisions
- `GET /api/v1/documents/:id/revisions` list document revisions
- `POST /api/v1/documents` create a document
- `POST /api/v1/documents/:id/revisions` create a revision and optionally upload `file` to Cloudinary using `multipart/form-data`

Revision numbers are generated by the API per document. The first revision is `000`, then `001`, `002`, and so on.

Swagger docs are available at:

```text
http://localhost:3000/api/docs
```

Module-level API docs live beside the source in `src/api/v1/*/README.md`.

Successful responses use this envelope:

```json
{
  "success": true,
  "path": "/api/v1/health",
  "timestamp": "2026-07-04T00:00:00.000Z",
  "data": {}
}
```

Paginated list responses are returned inside `data`:

```json
{
  "success": true,
  "path": "/api/v1/documents?page=1&limit=10",
  "timestamp": "2026-07-04T00:00:00.000Z",
  "data": {
    "items": [],
    "meta": {
      "total": 0,
      "page": 1,
      "limit": 10,
      "total_pages": 0,
      "has_next_page": false,
      "has_previous_page": false
    }
  }
}
```

For BigInt IDs, send values as strings in JSON bodies.
